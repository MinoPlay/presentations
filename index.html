Damien Garros · What Should You Build?

AI changes the question from “can we?” to “should we?”

Build

Maximum fit

You own every maintenance cost.

Assemble

The practical middle

Build what differentiates. Standardize the seams.

Buy

Fast leverage

Someone else’s roadmap.

My takeaway

Don’t ask agents to invent the city. Give them building blocks, blueprints and standards.

Bart Dorlandt · JSON Freedom or Chaos

Flexibility without validation is deferred chaos.

The rookie path

  • Accept arbitrary JSON
  • Discover drift at runtime

The engineering path

  • Model the contract
  • Validate with Pydantic, test with pytest

Marcus Hoff · Vibe-ops

AI did exactly what he said, not what he meant.

Task: refactor and migrate the infrastructure with AI, in one go.
Result: locked out of the systems.
Rescue: backup access, and AI again.
Lesson: AI follows the request, but misses the intent behind it.

Ahmed Shawky · Memory Has No Changelog

Experts remember a process that history does not confirm.

Ask the experts

  • 90-page reports
  • Conflicting, full of screenshots
  • Unusable for automation

Reverse-engineer history

  • Mine historical data, weave in the reports
  • Test for acceptance, not identical results
  • Study the error cases
The workflow

Which panels and trunks should workers use when setting up the network?

Niclas Skøtt Petersen · When Your Source of Truth Isn't Yours

Uncoordinated changes break integrations.

What breaks things

  • Other systems depend directly on yours
  • Changes are not coordinated
  • No backwards compatibility

What keeps it working

  • Stable, versioned interfaces
  • Backwards compatibility
  • Tests across systems, clear ownership

Urs Baumann · Laziness: A Blessing or a Curse?

The funniest talk made the simplest point.

We automate because we are too lazy to repeat ourselves.

But useful laziness has standards

Good laziness eliminates toil and leaves a tested, maintainable system. Bad laziness chases the newest tool instead of fixing fundamentals.

Key takeaways

Automation is becoming ordinary software engineering.

01Network engineers are adopting more and more software development concepts.

02The question is no longer “can I build it?” but “should I build it?”

03AI was a small part of the day, apart from Ahmed’s and the opening talk.

04A funny twist: we automate because we are lazy.

My take

AI is an excavator, not a shovel. It moves more earth, so it matters even more where you point it.
